\*\* below is how the basically DockerFile performes

\*\* 1. `FROM python:3.8-slim-buster`

- Specifies the **base image** for the Docker image.
- Uses **Python 3.8** with the lightweight `slim-buster` Linux environment.
- Provides Python and the basic OS environment required by the application.

2. `WORKDIR /app`
   - Sets `/app` as the **working directory inside the Docker container**.
   - All following commands will be executed from this directory.
   - If `/app` doesn't exist, Docker creates it automatically.

3. `COPY . /app`
   - Copies all files and folders from the **current project directory** on your computer into `/app` inside the container.
   - `.` means the current directory.
   - `/app` is the destination inside the container.

4. `RUN apt update -y && apt install awscli -y`
   - `RUN` executes commands **while building the Docker image**.
   - `apt update` updates the Linux package information.
   - `apt install awscli` installs the **AWS CLI** inside the image.
   - `-y` automatically answers "yes" during installation.
   - `&&` means the second command runs only if the first command succeeds.

5. `RUN pip install -r requirement.txt`
   - Installs all Python packages listed in `requirement.txt`.
   - For example, it can install Flask, pandas, NumPy, scikit-learn, etc.
   - These packages become part of the Docker image.

6. `CMD ["python3","app.py"]`
   - Specifies the **default command that runs when a container is started**.
   - In this case, it starts the Flask application using `app.py`.
   - Unlike `RUN`, `CMD` executes when the **container starts**, not when the image is built.

7. `Dockerfile`
   - A text file containing instructions for **building a Docker image**.
   - Docker reads the instructions from top to bottom and creates the image accordingly.

\*\* this is how it runs after it goes to the aws ecr and ec2
You push your code to GitHub.
GitHub Actions automatically starts when code is pushed to the main branch.
GitHub Actions uses actions/checkout to download your latest project code.
GitHub Actions configures AWS credentials so it can access AWS services.
GitHub Actions logs in to Amazon ECR (Elastic Container Registry).
Docker builds an image using your Dockerfile.
The Docker image contains your application code, Python environment, libraries, dependencies, and required configuration.
GitHub Actions tags the Docker image with the ECR repository address.
GitHub Actions pushes the Docker image to Amazon ECR.
ECR acts like a storage/warehouse for Docker images.
GitHub Actions connects to your EC2 server using SSH.
EC2 logs in to Amazon ECR and pulls the latest Docker image.
EC2 stops the old Docker container if one is already running.
EC2 removes the old container.
EC2 runs a new container using the latest image downloaded from ECR.
Your ML application is now running inside a Docker container on EC2.

****\*\*\***** here is the entire steps to creat a ci/cd pipeline using ecr and ec2 instance in aws.

1. Created an **IAM User** in AWS and provided the required permissions for **Amazon ECR** and **Amazon EC2**.

2. Created an **Amazon ECR (Elastic Container Registry)** repository with **Private** visibility.

3. Copied the **ECR repository URI**, which will be used later in the Docker deployment process.

4. Created an **EC2 instance (virtual server)** in AWS and launched the instance.

5. Checked that the EC2 instance was in the **Running** state and connected to it using the **SSH/EC2 terminal**.

6. Updated and upgraded the Ubuntu packages using:

   ```bash
   sudo apt-get update -y
   sudo apt-get upgrade
   ```

7. Downloaded the Docker installation script:

   ```bash
   curl -fsSL https://get.docker.com -o get-docker.sh
   ```

8. Installed Docker:

   ```bash
   sudo sh get-docker.sh
   ```

9. Added the `ubuntu` user to the Docker group so Docker commands can be executed without `sudo`:

   ```bash
   sudo usermod -aG docker ubuntu
   ```

10. Applied the Docker group changes to the current session:

```bash
newgrp docker
```

11. Went to the **GitHub repository → Settings → Actions → Runners → New self-hosted runner**.

12. Selected the required operating system and architecture for the EC2 server, then copied and executed the runner installation commands in the EC2 terminal.

13. While configuring the GitHub self-hosted runner:

- **Runner group:** Can be left as default by pressing `Enter`.
- **Runner name:** Give a meaningful name such as `self-hosted`.
- The runner name helps identify the EC2 machine in the GitHub repository.

14. After completing the runner setup, the runner appears under the **GitHub repository → Settings → Actions → Runners** section.

15. When the runner shows as **Idle/Online**, it means the EC2 virtual server is successfully connected to GitHub and is ready to execute GitHub Actions jobs.

16. The workflow can use:

```yaml
runs-on: self-hosted
```

This tells GitHub Actions to execute that particular job on the EC2 self-hosted runner instead of a GitHub-hosted machine.

17. Went to **GitHub → Repository → Settings → Secrets and variables → Actions**.

18. Created the required **GitHub Actions secrets**:

- `AWR_ECR_LOGIN_URI`
- `AWS_ACCESS_KEY_ID`
- `AWS_REGION`
- `AWS_SECRET_ACCESS_KEY`
- `ECR_REPOSITORY_NAME`

19. These secrets allow GitHub Actions to securely authenticate with AWS and access the ECR repository without writing the credentials directly inside the workflow file.

20. `AWR_ECR_LOGIN_URI` contains the **ECR registry URI**, for example:

```text
123456789012.dkr.ecr.ap-south-1.amazonaws.com
```

21. `ECR_REPOSITORY_NAME` contains the ECR repository name:

```text
studentperformanceindicator-docker-deployed
```

22. `AWS_REGION` contains the AWS region where the ECR repository and related resources are located, for example:

```text
ap-south-1
```

23. Created an **Inbound Security Group rule** for the EC2 instance to allow users to access the Flask application.

24. Added the inbound rule:

```text
Type: Custom TCP
Port: 8080
Source: 0.0.0.0/0
```

25. Port **8080** is opened because the Flask application is running on:

```python
app.run(host="0.0.0.0", port=8080)
```

26. Docker exposes the same port using:

```bash
-p 8080:8080
```

27. Therefore, after successful deployment, the application can be accessed using:

```text
http://<EC2-Public-IP>:8080/
```

28. The overall deployment architecture is:

```text
GitHub Repository
       ↓
GitHub Actions
       ↓
Build Docker Image
       ↓
Push Docker Image
       ↓
Amazon ECR
       ↓
Self-Hosted GitHub Runner
       ↓
EC2 Virtual Server
       ↓
docker pull
       ↓
docker run
       ↓
Flask ML Application
       ↓
Port 8080
       ↓
User's Browser
```

29. In this setup, **ECR stores the Docker image**, while **EC2 runs the Docker container**.

30. The GitHub self-hosted runner acts as the connection between **GitHub Actions and the EC2 virtual server**, allowing the deployment commands to execute directly on the EC2 machine.
